* Essentials
** CMD
- ~dir \\<ip\Share\~
- ~net use n: \\<ip>\share /user:plaintext Pass~
- ~dir n: /a-d /s /b | find /c ":\"~
  - ~/a-d~ -> =/a=: attr, =-d=: not dirs
  - ~/s~ -> displays files in specified directory & all subdirs
  - ~/b~ -> uses bare format (no heading info or summary)
  - ~| find /c ":///"~ -> processes o/p of cmd before pipe
- ~findstr /s /i cred n:\*.*~

* Concept of Attacks
- based on 4 cats that occur for each vuln
  
** Source
- source of info used for specific task of process
- doesn't matter which protocol used because HTTP header injections and buf overflows can be manipulated manually
- [[https://cve.mitre.org/cgi-bin/cvename.cgi?name=cve-2021-44228][Log4j]]
  
*** Information Sources
**** Code
- already exec'd program code results used as source of information
**** Libraries
- collection of program resources
- include config data, docss, help data, msg templates, prebuilt code, subroutines, classes, vals, type specs
**** Config
- static/prescribed vals that determine how process processes info
**** APIs
- interface of programs for retrieving/providing info
**** User I/P
- manual entry of info by user

** Process
- processing information fwd from source
- processed according to intended task det by program code.
- for each task dev specs how info processed
- occurs using classes w diff functions, calcs, loops

*** Process Components

**** PID
- ID process being started or is already running
- running procs have already assigned privileges, new ones started accordingly

**** Input
- i/p of info
- assigned by user or result of programmed function

**** Data Processing
- hard-coded fn() of program dictate how info rcvd is processed.

**** Variables
- used as placeholders for info that diff fn() can further process

**** Logging
- events documented and stored in reg or file

** Privileges
- present in any system that controls processes.
- type of permission that determine what tasks and actions can be performed

*** Privileges
**** System
- highest
- allow any system mod
- =SYSTEM= && =root=
  
**** User
- assigned to specific user

**** Groups
- atleast one user who has perms to perform some actions

**** Policies
- determine execution of application-specific commands
- can apply to grouped || individual users & actions

**** Rules
- perms to perform actions handled from w/in apps

** Destination
- where changes will be made
- can point to local or remote process

*** Destination

**** Local
- system env in which process occurred
- results either processed further by process that includes changes to data sets or storage of data

**** Network
- matter of fwd results of process to remote interface (IP addr || entire network)
- results can even influence route.
