* Attacking Email Services
- sending -> =SMTP=
- downloading -> =POP3= / =IMAP4=

** Enumeration
- complex and require us to enum multiple servers, ports, services
- most companies have cloud
- can use =Mail eXchanger= (=MX=) DNS record to ID mail server.
  - specifies mail server responsible for accepting email msgs
- =host= or =dig= & [[https://mxtoolbox.com/][MXToolbox]]

*** HOST - MX records
#+begin_src bash
host -t MX <domain>
#+end_src

*** DIG - MX records
~dig mx <domain> | grep "MX" | grep -v ";"~

*** HOST - A Records
- ~host -t A <domain>~

*** PORTS
**** Unencrypted
1. =25= -> SMTP
2. =143= -> IMAP4
3. =110= -> POP3
**** Encrypted
1. =465= -> SMTP
2. =587= -> SMTP (*STARTTLS*)
3. =993= -> IMAP4 Encrypted
4. =995= -> POP3 Encrypted
   
** Misconfigurations

*** Authentication
- SMTP server has diff cmds to use to enum valid usernames =VRFY=, =EXPN=, =RCPT TO=
- possible to password spray if enum valid usernames
  
**** VRFY
- instructs recieving SMTP server to check validity of particular email username
- server will respond indicating if user exists or not
  - can be disabled
#+begin_src bash
biscuitrescue@htb[/htb]$ telnet 10.10.110.20 25

Trying 10.10.110.20...
Connected to 10.10.110.20.
Escape character is '^]'.
220 parrot ESMTP Postfix (Debian/GNU)


VRFY root

252 2.0.0 root


VRFY www-data

252 2.0.0 www-data


VRFY new-user

550 5.1.1 <new-user>: Recipient address rejected: User unknown in local recipient table
#+end_src

**** EXPN
- similar to =VRFY=, but when used w distro list, will list all users on that list
- can be bigger problem than =VRFY=, since sites have alias = *"all"*
