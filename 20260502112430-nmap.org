* Enumeration
identifying all the ways we could attack target we must find.
- ways to access narrow down to:
  - =Functions and/or resources that allow us to interact with the target and/or provide additional information.=
  - =Information that provides us with even more important information to access our target.=

* Host Enumeration
** Host Discovery
- most effective -> *ICMP echo requests*
- recommended to store every scan

#+begin_src bash
sudo nmap <target ip> -sn -oA | grep for | cut -d "" -f5
#+end_src

|--------------------+--------------------------------------------------------|
| *scanning options*   | *Description*                                            |
| 10.129.2.0/24      | target IP range                                        |
| -sn                | disables port scanning                                 |
| -oA                | stores result in all formats starting with name 'tnet' |
| -iL                | Performs defined scans against targets in list         |
| --reason           | display reason for specific result                     |
| -PE                | perform scan using *ICMP Echo Requests*                  |
| --disable-arp-ping | disables *ARP Ping*                                      |
| -n                 | Disable DNS Resolution                                 |
|--------------------+--------------------------------------------------------|

- scanning method only works if Firewall of hosts allows it
** Scan IP List
#+begin_src bash
sudo nmap -sn -oA tnet -iL hosts.lst | grep for | cut -d" " -f5
#+end_src

**** ICMP Echo Request
- if we disable port scan (=-sn=), Nmap ping scans w *ICMP Echo Requests* (=-PE=)
- Once sent, we expect *ICMP Reply* if pinging host is alive.
- prev scans didnt do so because before ICMP, it would send *ARP ping* and rcv *ARP reply*

** Host & Port Scanning
- we need info including
  - Open ports and services
  - service versions
  - info that services provided
  - OS
- 6 diff states for scanned port

|------------+------------------------------------------------------------------|
| *States*     | *Description*                                                      |
| open       | indicates connection to scanned port has been established.       |
|            | connection can be *TCP, UDP, SCTP*                                 |
| closed     | TCP indicates that the packet we rcvd back contained *RST* flag.   |
|            | This method can be used to determine if host is alive            |
| filtered   | nmap can't correctly id whether open/closed. Either no response  |
|            | returned from target for port, or we get error code from target. |
| unfiltered | only occurs during *TCP-ACK* scan. means that port is accessible,  |
|            | but cannot be determined whether open/closed                     |
| open\      | if we dont get response for specific port. indicates firewall/   |
| filtered   | packet filter                                                    |
|            |                                                                  |
| closed\    | only occurs in *IP ID idle* scans and indicates that it was        |
| filtered   | impossible to determine if port closed/filtered by Firewall      |
|------------+------------------------------------------------------------------|

*** Discovering Open TCP Ports
- by default, nmap scans top 1000 TCP w SYN scan (~-sS~)
- (~-sS~) default when root, otherwise (~-sT~)

**** defining ports
- ~-p 22, 25, 80~ 
- ~-p 22-445~
- ~--top-ports=10~ -> from nmap db which have signed as most freq.
- ~-p-~ -> all ports

*** Connect scan (aka: full TCP connect scan)
- ~-sT~ -> [[https://nmap.org/book/scan-methods-connect-scan.html][TCP Connect Scan]]
- uses TCP 3-way handshake
- sends =SYN= packet & waits for response
- open if =SYN-ACK=, closed if =RST=
- highly accurate (completes 3-way TCP handshake)
