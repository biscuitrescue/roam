*** Forced Authentication Attacks
- can abuse SMB by creating fake SMB Server to capture users' *NetNTLM v1/v2 hashes*
- tool -> =Responder= -> *LLMNR* (Link-Local Multicast Name Resolution), *NBT-NS* (NetBIOS Name Service), *MDNS* (multicast DNS) poisoner tool
- can setup fake services (including SMB) to steal NetNTLM v1/v2 hashes
- in default config -> finds NBT-NS traffic
- respond on behalf of servers the victim is looking for & capture NetNTLM hashes

**** Creating fake SMB server

~responder -I <interface name>~
- when user/system tries to perform *Name Resolution*, following procedures conducted by win machine to retrieve host IP addr by hostname
  1. hostname file share IP addr req
  2. local host file (=C:\Windows\system32\drivers\etc\hosts=) checked for suitable records
  3. if (!records) { switch to local DNS cache }
  4. if (!DNS_records) { query sent to DNS server }
  5. else { machine issues multicast query requesting IP addr of file share from other machines on netw }

#+begin_quote
Suppose a user mistyped a shared folder's name \\mysharefoder\ instead of \\mysharedfolder\. In that case, all name resolutions will fail because the name does not exist, and the machine will send a multicast query to all devices on the network, including us running our fake SMB server. This is a problem because no measures are taken to verify the integrity of the responses. Attackers can take advantage of this mechanism by listening in on such queries and spoofing responses, leading the victim to believe malicious servers are trustworthy. This trust is usually used to steal credentials.
#+end_quote

* Latest SMB Vuln (SMBGhost)
- [[https://arista.my.site.com/AristaCommunity/s/article/SMBGhost-Wormable-Vulnerability-Analysis-CVE-2020-0796][CVE-2020-0796]]
- consisted of compression mechanism in SMB v3.1.1 -> made win 10 ver 1903, 1909 vuln to attack by unauth attacker (*RCE + full access to remote target system*)
- =integer overflow= vuln in fn() of SMB driver that allows system commands to be overwritten while accessing memory.
- vuln occurred because at the time the fn() lacked bounds checking to handle size of data sent in process of SMB session negotiation

** Concept of Attack
- occurs while processing malformed compressed msg after =Negotiate Protocol Responses=
- if SMB server allows requests, compression is generally supported
- client & server set terms of comm before client sends any data
- if data transmitted exceeds int var limits d/t to amount of data, parts written into buf -> leads to overwriting of subsequent CPU instr & interrupts process's normal exec
- data sets can be structured so that overwritten instr are replaced w our own, forcing CPU to perform other tasks & instructions

** Initiation of Attack
1. client sends req manipulated by attacker to SMB server (=CoA Source=)
2. sent compressed packets processed according to negotiated protocol responses (=CoA Process=)
3. process performed w atleast admin priv (=CoA Privileges=)
4. local process used s dest, _c_ should process compressed packets (=CoA Destination=)

** Trigger RCE
1. sources used in second cycle from prev proc =source=
2. int overflow occurs by replacing overwritten buf w attacker's instr & forcing CPU to exec those instr
3. same priv of SMB server used
4. remote attacker system used as dest, granting access to local system
