* Payload
- module which aids exploit module in returning shell to attacker.
- sent together with exploit to bypass std functioning proceduress of vuln services (=exploits job=)

1. [[#singles][Singles]] -> =windows/shell_bind_tcp=
   =windows/shell/bind_tcp=
2. [[#stager][Stagers]] -> =bind_tcp=
3. [[#stage][Stages]] -> =shell=

**** Singles
contains exploit && shellcode for sel task.
- inline payloads -> more stable (contain everything)
- may not be supported by some exploits because of size.

**** Stager
work with [[#stage][stage]]. perform spec task.
- runs on victim machine.
- initiates outbound connection to attacker's listener
- designed to be small & reliable
- default -> appr stager for given scenario (fallback -> less-preferred)

**** Stage
- payload component downloaded by stager's modules.
- eg: =Meterpreter=, =VNC Injection=
- payload stages automatically use middle stagers
  - single ~recv()~ fails with large payloads.
  - stager recievers middle stager.
  - middle stager performs full download
  - better for RWX

** Staged Payloads
*Exploitation Process* which is modularised and functionally separated.
- Goal -> Be compact and inconspicous.
# Help with Antivirus / IPS evasion

**** =Stage0= -> init shellcode sent over net to target
- init connection back to attacker.
- aka: reverse connection.
- =reverse_tcp=, =reverse_http=, =bind_tcp= -> ~show payloads~
- attempts to read larger payload into mem (=stage1=)

**** Reverse Connections
more effective -> leverage outbound traffic rules. (inbound = stricter)


** Meterpreter ([[id:451415a9-7083-48a5-b804-4aa959047ec1][depth]])
- Uses =DLL Injection=
  - ensures connection to victim is:
    - stable
    - hard to detect by simple checks
    - persistent across reboots / sys changes

- resides completely in mem of remote host.
- no trace on hard drive.
- v difficult to detect with conventional forensics.
- plugins loaded/unloaded dynamically

**** after exec
- new session created.
- all avl cmds aimed at target system.
- keystroke capture, passwd hash collection. microphone tapping, ss to impersonate process Security tokens.

* Meterpreter
:PROPERTIES:
:ID:       451415a9-7083-48a5-b804-4aa959047ec1
:END:
- multi-faceted extensible
- used =DLL Injection= -> ensures connection to victim host is stable & difficult to detect using simle checks
- resides in mem of remote hosts
- leaves no trace on hard drive
- ~show payloads~

** Running
after exec:
- target execs init stager. (usually bind, reverse, findtag, passivex etc)
- stager loads DLL prefixed w reflective. reflective stub handles unloading/injection of DLL
- core inits, establishes AES-encrypted link over socket, sends GET.
- msf rcvs GET, configs client.
- loads extensions. always loads =stdapi= =priv= if module gives admin rights.

** Stealthy
- resides entirely in mem, writes nothing to disk.
- no new processes created when Meterpreter injects itself into compromised dev
- perform process migrations.
- all meterpreter payload comms b/w target and us are encrypted using AES
# all of these provide ltd forensic evidence

** Powerful
uses channelised comms system b/w target host and attacker.
- allows for AES encrypted traffic

** Extensible
augmented at runtime & loaded over network. allows new functionality to be added w/out rebuilding (*modular*)

* Firewall & IPS/IDS Evasion
** Endpoint Protection
- any localised dev/serv whose sole purpose is to protect single host on net

- comes in form of software packs (=Antivirus Protection=, =Antimalware Protection=, =Firewall=, =Anti-DDOS= in same package)
  
*** Perimeter Protection
- comes in physical/virtualised devs on network Perimeter edge.
- =edge devs= provide access inside of network from outside. (=public= to =pvt=)
- can find =DMZ= between =public= & =priv=
**** DMZ
- Lower-sec policy level zone than inside net, but higher trust than outside.
- virtual space where public-facing servers are housed
  - push, pull data for public clients from internet, but also managed from inside and updated w patches, info etc
** Security Policies
- fn() same way as =ACLs=
- list of =allow= and =deny= stmts -> dictate how traffic/files can exist w/in config.
- can target different features of net & hosts depending on where they reside:
  + Network Traffic Policies 
  + Network Traffic Policies
  + Application Policies
  + User Access Control Policies
  + File Management Policies
  + DDoS Protection Policies
  + Others

**** Security Policies:
***** Signature-based
The operation of packets in the network and comparison with pre-built and pre-ordained attack patterns known as signatures. Any 100% match against these signatures will generate alarms.
***** Heuristic / Statistical Anomaly Detection
Behavioral comparison against an established baseline included modus-operandi signatures for known APTs (Advanced Persistent Threats). The baseline will identify the norm for the network and what protocols are commonly used. Any deviation from the maximum threshold will generate alarms.
***** Stateful Protocol Analysis Detection
Recognizing the divergence of protocols stated by event comparison using pre-built profiles of generally accepted definitions of non-malicious activity.
***** Live-monitoring and Alerting (SOC-based)
A team of analysts in a dedicated, in-house, or leased SOC (Security Operations Center) use live-feed software to monitor network activity and intermediate alarming systems for any potential threats, either deciding themselves if the threat should be actioned upon or letting the automated mechanisms take action instead.
** Evasion Techniques
- most host-based AV software rely on =Signature-based Detection= to id aspects of malicious code.
- these signatures places inside AV Engine -> used to scan storage space & running procs for matches
- [[https://www.zdnet.com/article/us-government-releases-post-mortem-report-on-equifax-hack/][US Govt Post-Mortem report on Equifax Hack]]

- [[https://channelpostmea.com/wp-content/uploads/2017/08/infoblox-whitepaper-data-exfiltration-and-dns-closing-the-back-door.pdf][Stopping data Exfil and Malware Spread through DNS]]
