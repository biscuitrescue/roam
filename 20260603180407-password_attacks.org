* Cracking Techniques
- passwords commonly hashed when stored

***** Hashing
- mathematical function which transforms arbitrary number of i/p bytes into fixed size o/p (~MD5~, ~SHA-256~)
- designed to work in 1 direction

****** Techniques to crack passwords
******* Rainbow Tables -> [[*Rainbow Tables][Rainbow Tables]]
******* Dict attacks -> [[*Dict attacks][Dict Attacks]]
******* Brute Forcing -> [[*Brute Force][Brute Force]]

*** Rainbow Tables
- large precompiled maps of I/O values for given hash function
- used to quickY ID pass if corresponding hash has already been mapped

***** Salting
- =salt= -> random sequence of bytes added to password before it is hashed.
- salt usually prepended, not a secret value because system has to know what salt was used to check password hash
- even if correct password has been mapped, combination of salt & pass has likely not

*** Dict Attacks
- =Wordlist= attack
- one of the most efficient techniques for cracking passwords

*** Brute Force
- attempting every possible combination of chars until correct pass discovered.
- can take very long time.

** John The Ripper
- brute-force & dict attacks

*** Cracking modes
**** Single Cracking Mode
- rule-based cracking -> linux creds
- generates passwords based on victim's username, homedir name, =GECOS= values (full name, room num, phone num)
- ~john --single passwd~
**** Wordlist Mode
- used to crack passwd w dict attack
- ~john --wordlist=<wordlist> <hash_file>~
**** Incremental mode
- powerful brute-force.
- generates passwd based on =Markov Chains=
- designed to test all char combinations defined by specific char set
- prioritises more likely passwds based on training data
- ~john --incremental <hash_file>~

* Extracting Passwords (Windows)

** Windows Authentication Process
- [[https://docs.microsoft.com/en-us/windows-server/security/windows-authentication/credentials-processes-in-windows-authentication][Windows Client Authentication Process]] involves multiple modules responsible for logon, cred retrieval, verification
- [[https://learn.microsoft.com/en-us/windows-server/security/credentials-protection-and-management/configuring-additional-lsa-protection][Local Security Authority]] =LSA= -> protected subsystem -> authenticates users, manages local plugins, local security, provides srv for Xlating b/w usernames & SIDs

****** Local Interactive Logon:
- =WinLogon= -> logon process
- =LogonUI= -> logon user interface process
- =LSASS= -> Local Security Authority Subsystem Service
- credential providers
- =SAM= -> Security Accounts Manager / =AD= -> Active Directory

*** LSASS
- comprised of multiple modules
- governs all auth processes
- =%SystemRoot%\System32\Lsass.exe=
- fwds security audit logs to =Event Log=
- [[https://docs.microsoft.com/en-us/previous-versions/windows/it-pro/windows-2000-server/cc961760(v=technet.10)?redirectedfrom=MSDN][Architecture]]
- each interactive session -> separate instance of WinLogon
- =Graphical Identification & Authentication= architecture loaded into process area used by winlogon -> rcvs creds -> invokes authentication interfaces via =LSAlogonUser= fn()

****** Auth Packages
******* Lsasrv.dll
- LSA server service
- enforces policies
- security package manager for LSA
- contains =Negotiate= fn()
******* Msv1_0.dll
- auth pkg -> local machine logons -> don't require custom auth
******* Samsrv.dll
- =SAM= stores local security accs
- enforces locally stored poIcies
- supports APIs
******* Kerberos.dll
- loaded by LSA for Kerberos based auth on machine
******* Netlogon.dll
- Net based logon srv
******* Ntdsa.dll
- Directory System Agent (DSA)
- manages =AD= DB (ntds.dit)
- processes LDAP queries
- replication b/w domain controllers
- loaded on domain ctrl'ers

*** SAM DB
- DB file in windows
- stores user account creds
- authenticate local & remote users
- cryptographic protections
- user passes as hash in registry -> =LM= / =NTLM= hashes
- =%SystemRoot%\system32\config\SAM=
- mounted under =HKLM\SAM=
- viewing/accessing requires =SYSTEM= lvl privileges

****** Workgroup/Domain
- systems can be assigned to Workgroup/Domain at setup
******* Workgroup
- SAM DB handles locally
- all existing users locally stored in DB
******* Domain
- Domain Controller (=DC=) must validTE creds from AD DB (ntds.dit) -> =%SystemRoot%\ntds.dit=

***** to prevent offline cracking of SAM DB
- =SYSKEY= (=syskey.exe=) -> Windows NT 4.0
- partially encrypts SAM file on disk w system gen key

*** Credential Manager
- builtin -> allows users to store & manage creds used to access nwtwork resources, websites, apps
- saved creds stored per user profile in user's =Credential Locker=
- creds encrypted & stored at =PS C:\Users\[Username]\AppData\Local\Microsoft\[Vault/Credentials]\=

*** NTDS
- database file which stores AD data:
  * user accounts (username & pass hash)
  * group accounts
  * computer accounts
  * group policy objects
